We are converting this project from a Next.js web app to a 
proper native iOS and Android app using Expo (React Native).

The entire backend (API routes, pipeline, scoring, scrapers, 
Supabase) stays exactly as-is and does not change. We are 
rebuilding the frontend only, as a new Expo app that calls 
the existing backend API.

4. API CLIENT
/mobile/lib/api.ts
════════════════════════════════

All backend calls go through this file.
Never call the backend directly from components.

const BASE_URL = process.env.EXPO_PUBLIC_API_URL;

async function apiCall(
  path: string, 
  options: RequestInit = {},
  session: Session | null
): Promise<any> {
  const response = await fetch(`${BASE_URL}${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${session?.access_token}`,
      ...options.headers,
    },
  });
  
  if (response.status === 402) {
    throw { type: 'usage_limit' };
  }
  if (!response.ok) {
    const err = await response.json();
    throw { type: err.error ?? 'unknown', message: err.message };
  }
  return response.json();
}

export const api = {
  chat: (messages: any[], session: Session | null) =>
    apiCall('/api/chat', {
      method: 'POST',
      body: JSON.stringify({ messages }),
    }, session),
    
  saveSearch: (address: string, result: any, session: Session | null) =>
    apiCall('/api/save-search', {
      method: 'POST', 
      body: JSON.stringify({ address, result_json: result }),
    }, session),
    
  getSearchHistory: (session: Session | null) =>
    apiCall('/api/searches', {}, session),
};

CODE:
import Purchases, { 
  PurchasesPackage,
  CustomerInfo 
} from 'react-native-purchases';
import { Platform } from 'react-native';

export async function initRevenueCat(userId: string) {
  const apiKey = Platform.OS === 'ios' 
    ? process.env.EXPO_PUBLIC_REVENUECAT_APPLE_KEY!
    : process.env.EXPO_PUBLIC_REVENUECAT_GOOGLE_KEY!;
  
  await Purchases.configure({ apiKey, appUserID: userId });
}

export async function getSubscriptionStatus(): Promise<boolean> {
  try {
    const info: CustomerInfo = await Purchases.getCustomerInfo();
    return typeof info.entitlements.active['pro_access'] !== 'undefined';
  } catch {
    return false;
  }
}

export async function purchasePro(): Promise<boolean> {
  try {
    const offerings = await Purchases.getOfferings();
    const pkg: PurchasesPackage | undefined = 
      offerings.current?.monthly;
    
    if (!pkg) throw new Error('No package available');
    
    const { customerInfo } = await Purchases.purchasePackage(pkg);
    return typeof customerInfo.entitlements.active['pro_access'] 
      !== 'undefined';
  } catch (err: any) {
    if (err.userCancelled) return false;
    throw err;
  }
}

export async function restorePurchases(): Promise<boolean> {
  const info = await Purchases.restorePurchases();
  return typeof info.entitlements.active['pro_access'] !== 'undefined';
}

SYNC WITH SUPABASE:
After successful purchase, update Supabase so the 
backend knows about the subscription:

async function syncSubscriptionToSupabase(
  userId: string, 
  isPro: boolean
) {
  await supabase
    .from('profiles')
    .update({ subscription_tier: isPro ? 'pro' : 'free' })
    .eq('id', userId);
}

Call this after purchasePro() and on app launch.

IMPORTANT NOTES FOR REPLIT
════════════════════════════════

1. The /mobile folder is a completely separate 
   Expo project from the Next.js app. They share 
   nothing except the backend API URL and Supabase 
   credentials.

2. Keep the Next.js app running — it is the backend 
   that the mobile app calls. Both run simultaneously.

3. Do not mix React Native components with React 
   web components. They are different and incompatible.

4. RevenueCat cannot be tested in Expo Go — 
   use a development build:
   eas build --profile development --platform ios
   
5. Apple requires a privacy policy before App Store 
   review. Create a simple one at 
   privacypolicygenerator.info before submitting.

6. Apple subscription review takes 1-3 days extra 
   on top of regular app review (usually 1-2 days).
   Budget a week for first submission.

Start with: scaffold the Expo project, get login 
working, get chat screen calling the backend, 
get a basic report rendering. Get that working 
on simulator first before touching RevenueCat.
